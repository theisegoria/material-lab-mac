# PBR Material Lab core and CLI

`PBRMaterialLab.cpp` is a deterministic C++23 derivation core with a stable C ABI in `include/PBRMaterialLab.h`. It has no Apple or game-engine dependency and is compiled into both native apps. The macOS `material-lab` CLI uses ImageIO to decode source images into straight RGBA8 sRGB, then writes self-contained `.pbrmaterial` directories. The CLI reads each source once, hashes and decodes those same bytes, and applies EXIF/TIFF orientation (matching PIL `exif_transpose`). Pixels are decoded **unpremultiplied** through vImage, so colour under partial or zero alpha is preserved; only if vImage cannot convert a format does it fall back to a premultiplied CoreGraphics draw (colour under alpha 0 becomes black). The C API expects callers on other platforms to supply an already converted sRGB buffer.

## Build and run

```sh
cmake -S core -B build/material-lab-core -G Ninja   # Release unless CMAKE_BUILD_TYPE is set; tests keep asserts
cmake --build build/material-lab-core
ctest --test-dir build/material-lab-core --output-on-failure
build/material-lab-core/material-lab --input surface.png --output output/surface.pbrmaterial --label "stone wall" --preset stone
build/material-lab-core/material-lab --validate output/surface.pbrmaterial
build/material-lab-core/material-lab --validate capture.pbrcapture
```

For a reviewed batch, `--catalog catalog.json --output output` accepts `items`, `materials`, or `assets`. Each record needs a string catalog-relative `path` or `relative_path`, an optional string `id`, and `label` or `material_label`. It is selected by JSON `reviewed: true` or `review_status: "approved"` / `"reviewed"`. `--include-unreviewed` deliberately opts in to candidates; every catalog bundle records `source_review_status` (`"reviewed"`/`"unreviewed"`) and `included_by_opt_in`. Paths must stay inside the catalog directory after canonicalisation: absolute paths, `..` path components and symlinked components fail (a name such as `foo..v2.png` is fine). The whole catalog is planned first, so duplicate IDs and unsafe paths fail before any derivation. A per-item failure stops the batch unless `--keep-going` is given; either way a summary is printed and the exit status is nonzero if anything failed. Existing outputs are refused before any decoding.

Recipe flags (algorithm 1.3.0, see [DERIVATION.md](../docs/DERIVATION.md)): `--preset` is applied first wherever it appears, then every other flag overrides it. Controls are `--height-strength`, `--polarity`, `--roughness`, `--roughness-variation`, `--ao-radius` (pixels of a 1024² reference; scales with the tile), `--ao-strength` (GTAO relief exaggeration, 0..4), `--normal-strength` (0..16, scales the whole estimated surface), `--normal-dx` (green-down −Y normals for DirectX targets; default is +Y/green-up), `--equalize` (low-frequency albedo delighting, 0..1), `--seamless` (offset cross-fade width, 0..0.45), `--no-tile`, `--bent-normal`, and `--metalness`. Raw `--relief-mask-r8` uses one byte per pixel (0 suppresses inferred relief, 255 keeps it). Raw `--height-override-r16le` uses two little-endian bytes per pixel and bypasses inference. Neither alters the source albedo. The CLI accepts an image prepared by any external pre-upscaler as ordinary input. It can also run an explicitly selected local executable **before** derivation with repeated `--pre-upscale-arg` tokens. Both `{input}` and `{output}` placeholders are required and are substituted in a single pass; each token is passed directly through `posix_spawn`, without a shell. The child runs in its own process group with stdin from `/dev/null`, stdout redirected to stderr (the CLI's stdout stays machine-readable), and no inherited descriptors besides those. `--pre-upscale-timeout SECONDS` (default 600) sends SIGTERM to the group, then SIGKILL after 5 s; SIGINT/SIGTERM received by the CLI are forwarded to the child, and temporary directories are removed. The executable may have its own network behavior, so choose a trusted offline tool. The bundle records original and processed SHA-256 hashes, executable basename and hash, argument template, dimensions, basenames and hashes of argument files (only arguments that contain a path separator are treated as files), and a verified optional `{output}.upscale.json` receipt. For a receipt, the manifest embeds its original JSON bytes as base64 so validation can recompute the declared receipt SHA-256 and compare the parsed fields. The CLI hashes the actual processed bytes at derivation time. Because temporary processed input is not stored in the bundle, later validation checks manifest and receipt consistency rather than independently rehashing those pixels. No upscaler is linked into the core or run by default.

For the sibling offline pinned Real-ESRGAN helper, set `PINNED_PYTHON` to its pinned Python 3.11 virtualenv interpreter and `VENDOR_PROJECT_ROOT` to the project that owns the verified model and dependency tree:

```sh
build/material-lab-core/material-lab --input surface.png --output output/upscaled.pbrmaterial --preset stone \
  --pre-upscale-exec "$PINNED_PYTHON" \
  --pre-upscale-arg -I \
  --pre-upscale-arg "$PWD/scripts/pinned_realesrgan.py" \
  --pre-upscale-arg --vendor-project-root --pre-upscale-arg "$VENDOR_PROJECT_ROOT" \
  --pre-upscale-arg --input --pre-upscale-arg '{input}' \
  --pre-upscale-arg --output --pre-upscale-arg '{output}' \
  --pre-upscale-arg --scale --pre-upscale-arg 2
```

The helper verifies its external pinned tree and writes a model/backend receipt; Material Lab checks the receipt hashes and embeds it as provenance. The bundled CLI test uses a small local resize stub to verify the hook without model dependencies.

## Inference contract

- Decode source color to linear RGB for luminance analysis. The CLI converts profile-tagged input through ImageIO to sRGB. Untagged input is treated as sRGB; record the source profile separately if that assumption matters.
- Flat is the default preset and produces neutral height and normals even for painted contrast. Stone, fabric, organic, coated metal, and bare metal presets weight 2, 8, and 24 reference-pixel bands of log luminance and scale the result to a per-preset rms surface slope. These are editable visual priors, not inverse-rendered physical geometry.
- Optional R8 mask suppresses only inferred relief. An authored R16 height override takes precedence over mask and preset and is exported unchanged. Estimated height is range-normalized 16-bit (0 = lowest, 65535 = highest; a flat result is 0.5) and the manifest's `relief.height_span_tile_widths` gives the depth it spans.
- Derive +Y (green-up, glTF/OpenGL) tangent-space normals by default, or −Y with `normal_y_down`, with RGB in linear 8-bit format, opaque alpha, blue upper hemisphere, and unit length within the receiving cooker's tolerance. Algorithm 1.0.0 bundles encoded green-down despite claiming +Y; the validator accepts them with a warning. AO is a GTAO heightfield estimate; 1 means unoccluded. Bent normals are an optional horizon diagnostic. Cavity, convexity, slope, and edge are heightfield diagnostics.
- Perceptual roughness starts from an assigned material prior and varies with concavity, micro-contrast and mineral-facet cues within the preset's physical range (standard deviation 0.25 × `roughness_variation`). ORM is exported only when metalness was explicitly assigned: R=AO, G=perceptual roughness, B=assigned metalness. RGB alone does not establish intrinsic roughness, metalness, F0, emission, opacity, thickness, or physical gameplay properties.
- Spatial filters may wrap at tile boundaries, but wrap does not repair nonmatching source edges. Seam metrics report opposite-edge height values, gradients, and linear albedo differences. A 3×3 preview belongs to the app UI; derived map bytes remain one tile each.

## Bundle format

The companion iPhone app transfers a bounded single-file `.pbrcapture` JSON envelope over the direct link and through Files/AirDrop. The CLI validates its 64 MiB limit, source PNG hash and 2..4096 square dimensions, optional original/derived hashes and dimensions, map encodings, and absence of GPS/location metadata. The desktop app imports a valid capture into its inbox before explicit export.

Each `.pbrmaterial` directory has `manifest.json` (with a `relief` object from 1.3.0) and PNGs named `albedo`, `height`, `normal`, `roughness`, `ao`, `cavity`, `convexity`, `slope`, `edge`, with optional `bent_normal` and `orm`. The manifest identifies the source basename and SHA-256 (no absolute paths), semantic label, preset and every parameter (1.1.0 adds `normal_strength`, `normal_y_down`, `ao_strength`, `albedo_equalize`, `seamless_blend`), top-level `normal_convention` (`"+Y"`/`"-Y"`), algorithm version, map SHA-256/encoding/provenance, seam metrics, and `runtime_admitted: false`. Validation requires `runtime_admitted` to be the JSON boolean `false`, type- and range-checks every recipe value (the new fields are required for 1.1.0), allows only known map roles, requires all nine core maps with `file` equal to `<role>.png`, requires `orm`/`bent_normal` exactly when their recipe flag is set, compares hashes case-insensitively, and fully decodes every PNG (chunk CRCs, inflate size, row filters, bit depth, colour type, no interlace, sRGB tag only on albedo) as well as through ImageIO. PNGs are written with adaptive row filters at zlib level 6, encoded and hashed in memory, and written atomically. `.pbrcapture` recipes (`normalStrength`, `normalYDown`, `aoStrength`, `albedoEqualize`, `seamlessBlend`) follow the same rule for `algorithmVersion` 1.1.0. Albedo is sRGB RGBA8; height is R16 UNorm grayscale; all other maps are linear RGBA8. Optional game-engine cook/admission is a separate explicit step.

`PBRLabDerive` is synchronous and keeps every output buffer owned by its `PBRLabResult` until `PBRLabFreeResult`. The optional callback receives progress and can cancel by returning zero. The ABI version string is the algorithm version (`1.3.0`); 1.3.0 adds `PBRLabGetDerivationInfo`. Callers may derive on background threads with separate input/output objects; no global mutable state is used.

## Learned guide normals

`--learned-normals MODEL.mlpackage|.mlmodelc` runs a local Core ML tangent-normal estimator (the converted MoGe-2 ViT-S model) before derivation. When tiling it runs on a wrap-padded image and is folded back periodically. Its output is integrated to height, supplies large-scale form and the sign of the albedo-derived fine detail, and is fused with inferred relief by `--guide-weight` (default 1 when a guide is given). `--guide-normals PNG` supplies precomputed +Y tangent normals instead, `--save-guide-normals PNG` writes the estimator's output for reuse, and `--learned-cpu-only` avoids the Neural Engine for more reproducible output. The manifest records `recipe.guide_normal_weight` and a `guide_normals` provenance object with the model hashes, tiling and a hash of the guide normals. The model, tiling contract and conversion are documented in [docs/LEARNED_NORMALS.md](../docs/LEARNED_NORMALS.md).
